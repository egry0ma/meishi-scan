# 名刺スキャン（meishi-scan）

紙の名刺をスマホで次々に撮影し、Google スプレッドシートに1枚1行で登録する Web アプリです。

- 撮影ページ：https://egry0ma.github.io/meishi-scan/
- カメラに名刺をかざすと四角形を検出し、静止してピントが合った時点で自動撮影します（台形補正あり）。
- 撮りためた名刺をまとめて送信すると、Google Apps Script（GAS）が LLM で項目を抽出し、スプレッドシートに追加します。

## 構成

```
 スマホ（Safari / Chrome）
 ┌──────────────────────────────────────┐
 │ 撮影ページ index.html（GitHub Pages）  │
 │  ・OpenCV.js で四角形検出・台形補正     │
 │  ・未送信の名刺は IndexedDB に保存      │
 │  ・Google アカウントでログイン          │
 └──────────────┬───────────────────────┘
                │ fetch POST（text/plain, JSON）3件ずつ並行
                ▼
 ┌──────────────────────────────────────┐
 │ GAS ウェブアプリ gas/Code.gs           │
 │  （実行ユーザー：自分 / アクセス：全員） │
 │  1. ログインの確認（Google に問い合わせ）│
 │  2. カードIDで重複確認                  │
 │  3. 画像を Drive に保存 ───────────────┼──▶ Google Drive（非公開フォルダ）
 │  4. LLM で項目を抽出 ──────────────────┼──▶ Claude API / Gemini API
 │  5. スプレッドシートに1行追加 ─────────┼──▶ Google スプレッドシート（非公開）
 └──────────────────────────────────────┘
```

### なぜ GAS だけで作らないのか

GAS の HtmlService で作ったページは iframe のサンドボックス内で動くため、カメラ（`getUserMedia`）が使えません（実機でも `NotAllowedError` になりました）。そのため撮影ページは GitHub Pages に置き、GAS は受信と登録だけを担当します。

## ファイル

| パス | 内容 |
|---|---|
| `index.html` | 撮影ページ（GitHub Pages で公開） |
| `gas/Code.gs` | GAS のコード（参照用。GAS エディタに貼り付けて使う） |

## GAS 側のセットアップ

### 1. スプレッドシートとスクリプトを用意する

1. 登録先にする Google スプレッドシートを開く（新しく作っても、既存のものでも構いません）。
2. メニューの「拡張機能 → Apps Script」を開く。
3. `gas/Code.gs` の内容を貼り付けて保存する。
   - **新しいプロジェクトの場合**：`コード.gs` の中身を消して貼り付けます。
   - **既にスクリプトがあるプロジェクトの場合**：既存のコードは消さずに、「ファイル」の「＋ → スクリプト」で新しいファイル（例：`meishi`）を作り、そこに貼り付けます。中身は `MeishiScan` の中に閉じ込めてあり、外に出る名前は `setup`・`doGet`・`doPost` の3つだけです。既存のコードに同じ名前の関数があると片方が黙って上書きされるので、貼り付ける前に既存のコードをこの3つの名前で検索して、無いことを確認してください。

データは既存の「名簿(AI)」シートの末尾に追加されます（列は下の「書き込み先シートの列」を参照）。シートは自動では作りません。他のシートには触りません。

### 2. スクリプトプロパティを設定する

Apps Script エディタの「プロジェクトの設定（歯車）→ スクリプト プロパティ」で追加します。

| プロパティ | 必須 | 内容 |
|---|---|---|
| `PROVIDER` | | `claude` または `gemini`（省略時は `claude`） |
| `ANTHROPIC_API_KEY` | `claude` のとき | Anthropic の API キー |
| `GEMINI_API_KEY` | `gemini` のとき | Google AI Studio の API キー |
| `CLAUDE_MODEL` | | 省略時は `claude-sonnet-5-5` |
| `GEMINI_MODEL` | | 省略時は `gemini-3.6-flash` |
| `GEMINI_THINKING_LEVEL` | | 省略時は `low`。`none` にすると送らない |
| `TARGET_SHEET` | | 書き込み先のシート名。省略時は `名簿(AI)` |
| `CLIENT_ID` | ○ | 次の手順 3 で作る OAuth クライアント ID（`…apps.googleusercontent.com`） |
| `ALLOWED_DOMAIN` | | 送信を許可する Google Workspace のドメイン（例：`origami-vol.or.jp`）。`setup()` が自分のアドレスのドメインで作る |
| `ALLOWED_EMAILS` | | ドメインに関係なく送信を許可するアドレス（カンマ区切り）。組織外の人に試してもらうときに使う |
| `ADMIN_EMAILS` | | 撮影ページで「管理者向け」の欄（送信先の設定・接続テスト・参加用 QR）を見られるアドレス（カンマ区切り）。`setup()` が自分のアドレスで作る。ほかの人には欄そのものが表示されない |

`FOLDER_ID`、`SHEET_ID`、`ALLOWED_DOMAIN`、`ADMIN_EMAILS` は手順 4 の `setup()` が作るので、自分で入れる必要はありません。`ALLOWED_DOMAIN` と `ALLOWED_EMAILS` のどちらも無いときは、だれの送信も受け付けません。

### 3. ログイン用の OAuth クライアント ID を作る

撮影ページで「Google でログイン」を使うための ID です。秘密の情報ではありません（参加用の QR にも入ります）。

1. https://console.cloud.google.com/ を組織のアカウントで開き、プロジェクトを作る（例：`meishi-scan`）。
2. 「API とサービス → OAuth 同意画面」（または「Google Auth Platform」）を開き、次のように設定する。
   - ユーザーの種類：**内部**（組織のアカウントだけがログインできる）
   - アプリ名：`名刺スキャン` など、サポートメール：自分のアドレス
3. 「認証情報 → 認証情報を作成 → OAuth クライアント ID」を開き、次のように作る。
   - アプリケーションの種類：**ウェブ アプリケーション**
   - 承認済みの JavaScript 生成元：`https://egry0ma.github.io`
   - 承認済みのリダイレクト URI：空のままでよい
4. 表示された「クライアント ID」を、スクリプトプロパティ `CLIENT_ID` に入れる。

組織の管理者設定で、Google Cloud のプロジェクト作成や「内部」の同意画面が制限されていることがあります。その場合は管理者に相談してください。

### 4. `setup()` を1回実行する

1. エディタ上部の関数選択で `setup` を選んで「実行」する。
2. 初回は権限の承認を求められるので許可する（スプレッドシート、Drive、外部への接続、自分のメールアドレスの参照）。
3. 実行ログに「送信を許可：ドメイン origami-vol.or.jp」のように表示されることを確認する。

`setup()` は次のものを作ります。何度実行しても、既にある値は上書きしません。

- `FOLDER_ID`：マイドライブに作る「名刺スキャン画像」フォルダ
- `SHEET_ID`：このスプレッドシート（あわせて、書き込み先シートがあり、1行目の見出しが想定どおりかを確認します。違う場合はエラーで止まります）
- `ALLOWED_DOMAIN`：実行した人のアドレスのドメイン（gmail.com の場合は代わりに `ALLOWED_EMAILS` に自分のアドレス）

以前の版で作った `TOKEN` は使わなくなったので、スクリプトプロパティから削除して構いません。

### 5. ウェブアプリとしてデプロイする

1. 「デプロイ → 新しいデプロイ」を開き、種類で「ウェブアプリ」を選ぶ。
2. 次のとおり設定してデプロイする。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
3. 表示される「ウェブアプリの URL」（`/exec` で終わるもの）を控える。

注意：

- 「全員（Google アカウントを持つユーザー）」や「組織内のユーザー」にすると、撮影ページからの送信は CORS エラーで失敗します。必ず「全員」を選んでください。
- Google Workspace の管理者設定によっては「全員」を選べない場合があります。その場合は管理者に確認するか、個人の Google アカウントでスプレッドシートを作ってください。
- コードを変えたら「デプロイを管理 → 編集 → バージョン：新バージョン」で更新します。新しいデプロイを作ると URL が変わります。
- `/dev` で終わるテスト用 URL は使えません。

## 撮影ページの使い方

1. 管理者から受け取った参加用の QR をスマホのカメラで読み取る（またはリンクを開く）。撮影ページが開き、送信先が設定される（初回は OpenCV.js の読み込み（約10MB）に時間がかかります）。
2. 組織の Google アカウントでログインする（自動でログインの案内が出ます。出ないときは右上の「ログイン」から）。ログインした名前が「連絡先受領者氏名」に入ります。
3. 「カメラ開始」を押し、カメラの使用を許可する。
4. 名刺と色の差がある無地の机などに置き、全体が画面に入るようにかざす（白い名刺は暗めの机、紺や黒など色の濃い名刺は明るい机の上が撮りやすい）。名刺は縦向きでも横向きでも構いません。
   - 枠が灰色：小さすぎる（「もう少し近づけてください」）、または撮影済み
   - 枠が赤：光が反射して文字が白く飛んでいる。名刺の角度を少し変えてください
   - 枠が黄色：静止を待っているか、ピントを合わせている
   - 枠が緑：撮影できる状態。そのまま静止すると自動で撮影されます
   - 撮影後は「次の名刺に替えてください」と出ます。名刺をいったん画面から外すと次の撮影ができます
5. 撮った名刺は画面下に並びます。タップすると拡大表示と削除ができます。
6. 「送信（N件）」を押すと3件ずつ送信し、登録できたものから一覧から消えます。失敗したものは赤枠で残るので、もう一度「送信」を押してください。

補足：

- 未送信の名刺は端末内（IndexedDB）に保存されるので、ページを閉じたり再読み込みしても消えません。ただし iOS の Safari は、7日間そのサイトを開かないと保存データを消すことがあります。撮影したら早めに送信してください。
- プライベートブラウズでは保存が正しく動かないことがあります。
- 自動撮影されない理由がわからないときは、「設定」の「判定の詳細を表示する」をオンにしてください。画面に、四角形・大きさ・静止・ピント・反射の各条件が ○／✕ で表示され、どこで止まっているかがわかります。
- ピントは、静止している間にいちばん合った状態に近づいたところで撮影するので、通常は調整不要です。ぼけた写真が撮れる場合だけ、「設定」の「ピントの下限」を上げてください。
- 光が反射しているとき（真っ白に飛んでいる、または色の付いた名刺がてかって白っぽくなっている）は、「反射があります。角度を少し変えると文字が読みやすくなります」と表示します。撮影は止めないので、そのまま撮るか、名刺の角度や照明を変えてください。真上の照明を避け、横から光が入る場所で撮ると反射が減ります。
- 同じ名刺を再送信しても二重には登録されません。撮影時に付けたカードIDを Drive の画像ファイル名に含めており、それで重複を確認します。そのため「名刺スキャン画像」フォルダの画像の名前は変えないでください。

## ほかの人に使ってもらう（参加用の QR）

管理者が最初に1回だけ、自分の端末で送信先を設定する。

1. 撮影ページの「設定」→「管理者向け」を開き、GAS の URL と OAuth クライアント ID を入れて「保存」する。
2. Google でログインして「接続テスト」を押し、「接続できました」と出ることを確かめる。
3. 「参加用の QR を表示」を押し、相手のスマホのカメラで読み取ってもらう（またはリンクを送る）。

- QR とリンクに入っているのは、GAS の URL と OAuth クライアント ID だけで、合言葉は入っていない。送信できるのは、`ALLOWED_DOMAIN`（または `ALLOWED_EMAILS`）のアカウントでログインした人だけ。
- 参加者は、ログインするだけで使える。合言葉や名前を入力する必要はない。
- 特定の人を止めたいときは、Google Workspace でその人のアカウントを止めるか、`ALLOWED_DOMAIN` を外して `ALLOWED_EMAILS` で許可する人を列挙する。

## 書き込み先シートの列

「名簿(AI)」シートの1行目が次の見出しになっている前提です（括弧の全角・半角や空白の違いは区別しません）。

| 列 | 見出し | 入る値 |
|---|---|---|
| A | タイムスタンプ | 撮影日時 |
| B | 連絡先受領者氏名 | 撮影ページでログインした Google アカウントの名前 |
| C | 会社名 | 名刺から抽出 |
| D | 氏名 | 名刺から抽出 |
| E | 氏名(フリガナ) | 名刺に読みが印刷されていればその表記。無ければ空 |
| F | 電話番号 | 固定電話と携帯を「, 」区切りで |
| G | Email | 名刺から抽出 |
| H | エビデンス | Drive に保存した画像のリンク |

追加する行は、A列に値がある最後の行の次から探し、A〜H列がすべて空の最初の行です。名刺の情報が何も読み取れなかった画像は登録せず、失敗として返します。

## セキュリティ上の注意

- **API キーと GAS の URL はリポジトリにコミットしないでください。** API キーは GAS のスクリプトプロパティに、GAS の URL と OAuth クライアント ID は各端末のブラウザ（localStorage）にだけ保存します。
- **名刺画像や実データ（テスト用の写真を含む）はコミットしないでください。** `.gitignore` で画像ファイル、CSV、JSON などを除外しています。
- スプレッドシートと Drive のフォルダは**非公開のまま**運用してください。共有設定を「リンクを知っている全員」にしないでください。
- GAS のウェブアプリは「全員」がアクセスできますが、Google のログインの証明（ID トークン）が無いもの・偽物・期限切れ・このアプリ向けでないもの・許可していないアカウントのものは、何もせずに拒否します。また、書き込み専用で、登録済みのデータを返す機能はありません。
- ログインの証明は1時間で切れ、そのタブの中（sessionStorage）にだけ置きます。タブを閉じれば消えます。
- Google のログインの部品（`accounts.google.com/gsi/client`）は Google が随時更新するため、SRI のハッシュを付けられません。
- 名刺の画像は、抽出のために選んだ LLM 事業者（Anthropic または Google）に送信されます。社内規程で外部サービスへの送信が制限されていないか確認してください。
- OpenCV.js は jsDelivr から読み込み、Subresource Integrity（SRI）のハッシュで改ざんを検知します。バージョンを上げるときはハッシュも更新してください。
